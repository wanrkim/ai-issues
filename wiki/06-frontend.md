# 06. 화면

`web/index.html` 한 파일이다. HTML, CSS, 자바스크립트가 모두 그 안에 있고 `data/issues.json`만 읽는다. 빌드 과정이 없다.

외부에서 불러오는 것은 없다. 글꼴은 기기에 있는 것을 쓴다.

## 구조

```
app
├─ topbar (position: sticky, top: 0)
│  ├─ eyebrow    "AI 소식을 모아서"
│  ├─ titlebar   제목 + actions (갱신 시각, 메뉴 아이콘 자리)
│  └─ tabs       섹션 탭 5개 + 밑줄(ink)
└─ pager         섹션 페이지 5개를 가로로 담는다
   └─ page × 5
      └─ list → row × 최대 20
```

## 세로 스크롤

문서 자체가 스크롤한다. 사파리는 문서가 스크롤될 때만 하단 도구 막대를 반투명 알약으로 접고, 그때 목록이 그 뒤로 이어진다. 문서를 고정하고 안쪽 요소만 스크롤하면 사파리가 막대를 계속 펼쳐두어 목록이 그 위에서 끊긴다.

`topbar`는 화면 위에 붙어 있어서 스크롤해도 정렬과 탭을 계속 쓸 수 있다.

## 가로 이동

`pager`는 CSS 스크롤 스냅을 쓴다. 손으로 만든 터치 처리는 없다.

- `scroll-snap-type: x mandatory` — 페이지 경계에 붙는다.
- `scroll-snap-stop: always` — 한 번에 한 페이지씩만 넘어간다.

자바스크립트는 `pager`의 스크롤 위치를 읽어 탭 밑줄만 옮긴다.

## 탭 밑줄

밑줄은 별도 요소이고 기준 폭 100px을 고정한 뒤 `transform`의 `translateX`와 `scaleX`로만 움직인다. 폭을 직접 바꾸면 매 프레임 레이아웃을 다시 계산해서 끊긴다.

위치는 `pager.scrollLeft / pager.clientWidth`를 두 탭 사이에서 보간해 정한다. 탭의 위치와 폭은 탭을 그린 직후에 한 번 재두고 그 값을 쓴다.

## 페이저 높이

섹션마다 항목 수가 다르므로 높이를 맞춘다.

- **멈춰 있을 때**: `max(현재 섹션 높이, 화면 높이 − topbar 높이)`. 항목이 적은 섹션도 화면 끝까지 채워야 그 빈 영역에서 스와이프가 먹는다.
- **이동 중일 때**: 지나가는 두 섹션 중 큰 쪽에 맞춘다. 짧은 섹션 높이에 묶여 있으면 다음 섹션이 잘려 보인다. 이동 중에는 늘리기만 하고 줄이지 않는다. 줄이면 진행 중인 가로 스크롤이 밀려서 목록이 좌우로 튕긴다.
- 이동이 멈추고 150ms 뒤에 현재 섹션 높이로 맞춘다. 높이가 실제로 줄어든 경우에만 세로 스크롤을 목록 맨 위로 보낸다. 문서가 짧아지면 브라우저가 스크롤 위치를 임의로 당기기 때문이다.

현재 섹션 번호는 `requestAnimationFrame` 콜백에만 맡기지 않고 이동이 끝난 뒤 스크롤 위치에서 다시 계산한다. 콜백이 늦으면 높이가 이전 섹션에 묶인다.

## 접히는 헤더

문서를 8px 넘게 내리면 `app`에 `compact` 클래스를 붙인다.

- 눈썹 문구가 높이 0으로 줄고 위로 8px 밀리며 사라진다.
- 제목이 `transform: scale(.7)`로 줄어든다. `font-size`를 바꾸면 매 프레임 글자 배치를 다시 계산해서 끊긴다.
- 제목 줄의 아래 여백이 14px에서 10px로 줄어든다.

맨 위로 돌아오면 되돌아간다. 전환은 0.24초이다.

## 배경과 상태 표시줄

색이 어긋나지 않도록 스크롤과 무관한 구조로 둔다.

| 대상 | 색 | 이유 |
|---|---|---|
| `html` | `--bg-top` | 위로 당겼을 때 드러나는 색 |
| `body` | `--bg-top` | 사파리가 첫 화면의 상태 표시줄 색으로 쓴다 |
| `topbar` | `--bg-top` → `--bg-mid` 그라데이션 | 이 요소가 직접 갖는다. 스크롤 위치와 무관하게 항상 같다 |
| `pager` | `--card` | 목록이 놓이는 흰 바탕 |

사파리는 첫 화면에서는 `body`의 배경색을 상태 표시줄에 쓰고, 스크롤한 뒤에는 화면에 실제로 그려진 색을 다시 읽는다. 두 경우가 같으려면 `body`도 위쪽 색이어야 한다.

노치 여백(`env(safe-area-inset-top)`)은 `topbar` 안에 둔다. 부모인 `app`에 두면 `position: sticky`인 `topbar`가 부모의 안쪽 영역을 벗어나지 못해 노치 아래에서 멈추고, 그 위로 배경색 띠가 드러난다.

## 상태 관리

| 상태 | 값 | 저장 위치 |
|---|---|---|
| 선택한 섹션 | `all`(기본), `llm`, `media`, `hardware`, `capital` | `localStorage` 키 `ai-issues.section` |

정렬은 최신순 하나로 고정한다. 화면에서 고르는 자리를 없앴다.

`localStorage`를 읽고 쓰는 곳은 모두 `try` / `catch`로 감싼다. 사생활 보호 모드에서 예외가 날 수 있다.

## 목록 규칙

- 섹션마다 상위 20개까지 표시한다.
- 순위 숫자는 화면에 보이는 목록 안에서의 자리이다. 종합 순위가 아니다.
- 등락 삼각형은 종합 순위 기준 변화이다. 오르면 빨간 위쪽, 내리면 파란 아래쪽, 변화가 없거나 직전 순위가 없으면 표시하지 않는다.
- 항목에는 제목만 표시한다. 항목 사이는 1px 구분선으로 나눈다. 배경과 모서리, 그림자를 두지 않는다. 한 화면에 더 많은 항목이 보이게 하기 위해서다.
- 항목을 누르면 부제와 출처 목록이 펼쳐진다. 원문은 새 탭에서 연다.
- 목록은 `last_seen` 내림차순으로 정렬한다.

## resize 처리

가로 폭이 실제로 바뀔 때만 위치를 다시 잡는다. iOS는 주소 표시줄이 접히고 펴질 때마다 `resize`를 보내는데, 그때마다 다시 잡으면 이동 중이던 화면이 중간에 멈춘다.
