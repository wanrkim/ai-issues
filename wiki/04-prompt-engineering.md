# 04. 프롬프트

## 호출 구조

묶기와 판정을 **한 번의 호출**로 처리한다. 무료 등급의 일일 요청 한도가 모델당 20회여서 실행당 호출을 1회로 줄여야 하기 때문이다. 한도는 [01-architecture.md](01-architecture.md)에 기록한다.

호출에 넣는 것은 두 가지뿐이다.

- **현재 이슈**: 살아있는 이슈의 `id`, `title`, `subtitle`, `axis`
- **새 글**: 아직 어떤 이슈에도 배정되지 않은 글의 번호, 출처, 제목, 요약 일부(320자)

최근 48시간의 글 전체를 매번 넣지 않는다. 이 차분 입력이 비용을 결정한다.

## 모델

`gemini-3.8-flash`를 먼저 부른다. 503, 500, 429가 오면 같은 모델로 한 번 더 시도하고, 그래도 실패하면 `gemini-3.7-flash`, `gemini-3.6-flash` 순으로 넘어간다. 실제로 응답한 모델 이름을 `data/issues.json`의 `model` 필드에 기록한다.

## 프롬프트 전문

`scripts/rank.py`의 `PROMPT` 상수와 같은 내용이다. 한쪽만 바뀌면 안 된다.

```
너는 AI 소식을 다루는 큐레이터다. 아래 "새 글" 목록을 사건 단위로 묶어라.

[규칙]
1. 같은 사건을 다룬 글은 하나의 이슈로 묶는다. 사건이 다르면 다른 이슈로 나눈다.
2. "현재 이슈" 목록에 이미 있는 사건을 다룬 글이면 assignments에 그 이슈 id와 함께 넣는다.
3. 현재 이슈에 없는 사건이면 new_issues에 새 이슈를 만들고 해당 글 번호를 items에 넣는다.
4. AI와 관계없는 글은 assignments에도 new_issues에도 넣지 않고 버린다. 검색어가 우연히 일치했을 뿐인 일반 소비재 기사, 단순 주가 시황, 광고성 글이 여기에 해당한다.
5. 글 하나는 최대 한 곳에만 넣는다.
6. 모든 문구는 한국어로 쓴다.

[새 이슈의 필드]
- title: 무엇이 일어났는지 한국어 한 줄로 쓴다. 12자 안팎으로 짧게 쓴다. 예: "클로드 6.0 출시"
- subtitle: 왜 중요한지 또는 무엇이 달라지는지 한국어 한 줄로 쓴다. 예: "코딩 벤치마크 갱신"
- summary: 무슨 일이 있었고 왜 중요한지 한국어 세 문장에서 네 문장으로 쓴다. 200자 안팎으로 쓴다.
  읽는 사람이 원문 기사를 열지 않아도 사건을 이해할 수 있어야 한다.
  주어진 글에 없는 사실을 지어내지 않는다. 숫자와 회사 이름은 글에 있는 그대로 쓴다.
  "~한다" 형태의 평서문으로 쓴다.
- axis: 다음 넷 중 하나를 고른다.
    llm      언어모델과 AI 서비스, 코딩 도구의 출시와 업데이트
    media    영상 생성 모델과 이미지 생성 모델
    hardware GPU, HBM, 반도체, 디바이스
    capital  IPO, 투자 유치, 인수, 규제, 소송
- impact: 1에서 5 사이의 정수를 고른다.
    5  주요 랩의 새 메이저 모델 출시, 대형 IPO, 대형 인수
    4  주요 랩의 마이너 모델 출시, 주요 제품 출시, 대형 투자 유치
    3  기능 업데이트, 중견 기업 소식, 하드웨어 로드맵
    2  파트너십, 소규모 출시
    1  그 외

[현재 이슈]
{live_issues}

[새 글]
{new_items}
```

`{live_issues}`는 `id | 제목 | 부제 | 축` 형식의 줄 목록으로 바꾼다. 이슈가 없으면 `(없음)`을 넣는다.
`{new_items}`는 `번호 | 출처 | 제목 | 요약 일부` 형식의 줄 목록으로 바꾼다.

## 임팩트 기준표

| 값 | 기준 |
|---|---|
| 5 | 주요 랩의 새 메이저 모델 출시, 대형 IPO, 대형 인수 |
| 4 | 주요 랩의 마이너 모델 출시, 주요 제품 출시, 대형 투자 유치 |
| 3 | 기능 업데이트, 중견 기업 소식, 하드웨어 로드맵 |
| 2 | 파트너십, 소규모 출시 |
| 1 | 그 외 |

## 응답 형식

Structured output을 사용한다. `responseMimeType`은 `application/json`이고 스키마는 다음과 같다.

```json
{
  "type": "OBJECT",
  "properties": {
    "assignments": {
      "type": "ARRAY",
      "items": {
        "type": "OBJECT",
        "properties": {
          "n": { "type": "INTEGER" },
          "issue_id": { "type": "STRING" }
        },
        "required": ["n", "issue_id"]
      }
    },
    "new_issues": {
      "type": "ARRAY",
      "items": {
        "type": "OBJECT",
        "properties": {
          "items": { "type": "ARRAY", "items": { "type": "INTEGER" } },
          "title": { "type": "STRING" },
          "subtitle": { "type": "STRING" },
          "summary": { "type": "STRING" },
          "axis": { "type": "STRING" },
          "impact": { "type": "INTEGER" }
        },
        "required": ["items", "title", "subtitle", "summary", "axis", "impact"]
      }
    }
  },
  "required": ["assignments", "new_issues"]
}
```

## 응답 검증

모델이 스키마를 지켜도 값이 틀릴 수 있으므로 다음을 확인한다.

- `assignments`의 `issue_id`가 현재 이슈 목록에 없으면 버린다.
- `n`이 새 글 목록의 범위를 벗어나면 버린다.
- `new_issues`의 `axis`가 네 값 중 하나가 아니면 그 이슈를 버린다.
- `impact`가 정수가 아니면 그 이슈를 버린다. 정수이면 1에서 5 사이로 자른다.
- 글 번호가 하나도 남지 않은 새 이슈는 만들지 않는다.

## 요약 생성

이슈마다 세 문장에서 네 문장짜리 요약을 함께 만든다. 화면에서 항목을 펼쳤을 때 보여주며, 원문 기사를 열지 않아도 사건을 이해할 수 있게 하는 것이 목적이다.

요약을 쓰려면 재료가 필요하므로 새 글의 요약 일부를 160자에서 320자로 늘렸다. 호출 횟수는 그대로 실행당 1회이므로 일일 요청 한도에 영향이 없다.

2026-09-06 실행에서 만든 요약은 140자에서 155자 사이였다.

## 관찰 기록

2026-09-05 실행에서 새 글 291건 중 157건(54%)을 규칙 4에 따라 버렸다. Google News 검색이 문자열 일치로 동작해서 들어온 무관한 기사가 실제로 걸러진다. 관련 이슈는 [08-issues.md](08-issues.md)의 I-005이다.
