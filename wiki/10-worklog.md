## 2026-09-06 — Phase 4. 자동 실행

### 워크플로

2시간 주기(UTC 기준 매시 05분)로 돌고, Actions 화면에서 손으로도 돌릴 수 있다. 단계는 의존성 설치, `collect.py`, `rank.py`, `data/` 커밋이다. 앞선 실행이 끝나기 전에 겹치지 않도록 concurrency 그룹을 지정했고, 데이터가 바뀌지 않으면 커밋하지 않는다. 20분이 지나면 중단한다.

주기를 2시간으로 정한 근거는 무료 등급의 일일 요청 한도이다. 하루 12회 실행이고 실행당 LLM을 1회 부르므로, 모델을 바꿔 재시도하는 경우를 더해도 모델당 20회 안에 들어간다.

Gemini 무료 등급의 일일 요청 한도가 모델당 20회였다. 착수 문서의 15분 주기는 하루 96회 실행이라 약 5배 초과였다. 묶기와 판정을 한 번의 호출로 합치고 실행 주기를 2시간으로 바꿨다. I-001을 해결하고 보관했다.

### 화면에서 겪은 것

iOS 사파리 동작을 이 환경에서 재현할 수 없어서 여러 번 헛짚었다. 원인을 확정한 것들을 [07-design-guidelines.md](07-design-guidelines.md)의 안티패턴에 기록했다. 그중 두 가지가 컸다.

- **문서 스크롤을 막으면 안 된다.** 사파리는 문서가 스크롤될 때만 하단 도구 막대를 접는다. 문서를 고정하고 안쪽 요소만 스크롤하는 구조에서는 목록이 도구 막대 위에서 끊긴다. 뷰포트 단위를 바꿔도 해결되지 않는다.
- **가로 이동을 터치 이벤트로 직접 구현하지 않는다.** `scroll-snap-stop: always` 한 줄로 한 번에 한 페이지씩 넘어간다. 직접 만든 코드는 iOS가 주소 표시줄 때문에 계속 보내는 `resize`와 부딪혀 이동이 중간에 멈췄다.

### 제품 결정 변경

- 축을 제외하는 방식에서 섹션 하나를 고르는 방식으로 바꿨다. 탭은 전체를 포함해 5개이고 섹션마다 상위 20개까지 표시한다.
- 기본 정렬을 인기순에서 최신순으로 바꿨다.
- 스크롤하면 제목이 한 줄로 줄어드는 헤더를 넣었다. 제목 오른쪽에 메뉴 아이콘 자리를 비워 두었다.

### 이슈 변화

- I-001(무료 한도 미확인), I-003(한 축 쏠림)을 해결하고 `archive/issues/`로 옮겼다.
- 백로그에서 B-006(축별 가중치)을 닫고 B-009(결제 계정 복구)를 추가했다.

## 2026-09-05 — Phase 1. 수집

`scripts/collect.py`를 작성하고 출처 10종에서 항목을 가져오는 것을 확인했다. 결과를 `data/items.json`에, 조건부 요청 상태를 `data/fetch_state.json`에 저장한다.

### 1회 실행 결과 (2026-09-05 18:26 KST)

수집 2,846건 중 최근 48시간 항목 356건을 보관했다. 출처별 보관 건수는 Google News 309건, Hacker News 14건, SEC EDGAR 17건, Anthropic 4건, OpenAI 4건, NVIDIA Newsroom 3건, Hugging Face Hub 2건, Google DeepMind 1건, Hugging Face Blog 1건이다.

### 고친 내용

- **NVIDIA 피드 주소.** 착수 문서의 `nvidianews.nvidia.com/rss`는 XML이 아니라 HTML을 반환해서 0건이 나왔다. 같은 뉴스룸의 실제 피드 주소인 `releases.xml`로 바꿔서 20건을 받았다.
- **SEC EDGAR 정렬.** 전문 검색 API의 기본값이 관련도순이라 2020년 제출이 첫 결과로 왔다. `dateRange=custom`과 `startdt`, `enddt`로 최근 3일로 좁혔다.
- **제목 정규화.** HTML 엔티티를 되돌리고, Anthropic 페이지 제목 끝의 `\ Anthropic` 표기와 SEC 제출자 이름 끝의 `(CIK ...)` 표기를 제거했다.
- **신규 건수 계산.** 피드가 과거 글까지 반환해서, 48시간이 지난 항목을 매 실행마다 새 항목으로 넣었다가 바로 버렸다. 저장 결과는 맞았지만 출력한 신규 건수가 실제보다 훨씬 컸다. 보관 기간 필터를 병합 앞으로 옮겼다.

### 결정한 내용

- **외부 라이브러리는 `requests`와 `feedparser` 2개만 쓴다.** RSS와 Atom의 형식 차이를 직접 처리하면 출처마다 깨질 수 있다.
- **Google News 리다이렉트 주소를 따라가지 않는다.** 쿼리 6개에 각 100건이라 한 번 실행에 최대 600회의 추가 요청이 생긴다. 중복 제거는 제목 기준으로 하고, 리다이렉트 해석은 Phase 2에서 상위 이슈에 포함된 항목만 처리한다.
- **SEC EDGAR `User-Agent`에 `ai-issues wanrkim@gmail.com`을 보낸다.** SEC 정책이 이름과 이메일을 요구한다. 이 값은 SEC 요청에만 사용한다.

### 이슈 변화

- I-002(Anthropic 공식 RSS 없음)를 해결하고 `archive/issues/`로 옮겼다.
- I-004, I-005, I-006을 추가했다.

## 2026-09-05 — Phase 0. 저장소와 위키 뼈대

저장소 `ai-issues`를 만들고 폴더 구조, `CLAUDE.md`, 위키 6개 페이지, Pages 배포용 최소 `index.html`을 작성했다.

### 결정한 내용

- **위키 페이지를 6개만 만들었다.** 착수 문서는 12개 페이지를 정의했지만, Phase 0 시점에 10개가 제목만 있는 빈 파일이 된다. 빈 파일은 읽는 사람에게 정보를 주지 않고 SSOT 원칙과도 맞지 않는다. 각 페이지는 필요한 Phase에서 만들면서 내용을 채운다. 만들 시점은 `README.md` 인덱스에 기록했다.
- **GitHub Pages 배포 폴더를 저장소 루트로 정했다.** 브랜치 기반 Pages는 배포 폴더로 `/`와 `/docs`만 지원하므로 착수 문서가 정한 `/web`을 직접 지정할 수 없다. `/docs`를 쓰면 `data/issues.json`이 서비스되지 않아서 화면이 데이터를 읽지 못한다. 루트를 지정하면 두 폴더가 모두 서비스되고 폴더 구조도 착수 문서 그대로 유지된다. 대신 진입 URL 끝에 `/web/`이 붙는다. URL 단축은 백로그 B-007에 기록했다.
- **git 사용자 정보를 저장소 안에서만 설정했다.** 전역 설정이 비어 있어서 `wan / wanrkim@gmail.com`을 이 저장소에만 지정했다.
