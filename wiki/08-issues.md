# 08. 이슈

아직 해결하지 않은 이슈만 적는다. 해결한 이슈는 `archive/issues/`로 옮긴다.

## I-001. Gemini 무료 티어 일일 요청 한도를 확인하지 않았다

15분 주기로 실행하면 하루 96회를 실행한다. 실행 한 번에 묶기 1회와 판정 N회를 호출하므로 실제 호출 수는 96회보다 많다. 무료 티어 한도 안에 들어가는지 확인하지 않았다.

- 확인 방법: Gemini API rate limits 문서에서 `gemini-3.8-flash`의 무료 티어 RPD를 확인한다.
- 반영 위치: [01-architecture.md](01-architecture.md) 무료 한도 표.
- 처리 시점: Phase 2.

## I-003. 종합 순위가 한 축으로 채워질 수 있다

LLM/서비스 축의 소식 건수가 다른 축보다 많아서 상위 순위를 한 축이 차지할 수 있다.

수집 결과가 이 우려를 뒷받침한다. 2026-09-05 실행에서 보관 항목 356건 중 309건이 Google News에서 왔고, Google News 쿼리 6개 중 3개가 LLM/서비스 축이다.

- 축별 가중치는 미리 넣지 않는다. Phase 2에서 실제 순위 결과를 보고 결정한다.
- 처리 시점: Phase 2. 백로그 B-006과 연결된다.

## I-004. SEC EDGAR 전문 검색 결과에 소형 기업 제출이 많다

`"artificial intelligence"`로 8-K와 S-1을 검색하면 3일 기준 75건이 나온다. 대부분은 사업 설명에 이 문구를 넣은 소형 기업의 제출이고, 서비스가 다루려는 대형 IPO나 인수 소식이 아니다.

- 검색어를 좁히는 방법과 판정 단계에서 임팩트 1로 걸러내는 방법 중 무엇을 쓸지 정하지 않았다.
- 처리 시점: Phase 2. 판정 결과를 보고 결정한다.

## I-005. Google News 검색 쿼리가 주제와 무관한 기사를 함께 가져온다

`AI chip` 쿼리에서 아이폰 구매 시기를 다룬 기사가 들어왔다. Google News 검색이 문자열 일치로 동작하기 때문이다.

- 판정 단계에서 임팩트가 낮게 나오면 순위에서 밀려나므로 별도 필터를 먼저 넣지 않는다.
- 처리 시점: Phase 2. 상위 20개 출력에 이런 항목이 남는지 확인한다.

## I-006. OpenAI와 Hugging Face Blog 피드가 전체 아카이브를 반환한다

한 번 요청에 OpenAI는 1,170건, Hugging Face Blog는 859건을 반환한다. Hugging Face Blog는 `ETag`를 제공해서 변경이 없으면 건너뛰지만, OpenAI는 제공하지 않아 15분마다 전체를 받는다.

- 보관 기간 필터가 병합 전에 걸러내므로 저장 용량 문제는 없다. 실행 시간과 트래픽만 늘어난다.
- 처리 시점: Phase 4에서 실행 시간을 측정한 뒤 판단한다.
